# 04 · 安全与回滚

> 用户明确要求：「删除或禁用环境配置 Skill 前的确认与回滚机制」。
> 本篇是这套机制的完整说明。

---

## 1. 三档收尾（必须让用户选，不许自动删）

环境配置技能完工后**不会自己消失**。它汇报并让用户三选一：

| 档 | 做什么 | 可逆性 | 适用 |
|---|---|---|---|
| **A. 禁用**（推荐） | 把 SKILL.md frontmatter 的 `disable: false` 改成 `true` | 改回 `false` 即恢复 | 想留着以后换机器/换环境重跑 |
| **B. 归档** | 整个 skill 目录移到 `$VW_CONFIG_ROOT/archive/<名字>-<时间戳>/` | 移回来即恢复 | 不想让它在技能列表里，但留着备用 |
| **C. 删除** | 真删目录（**先自动备份**） | 用备份恢复 | 确定不再需要 |

**默认推荐 A（禁用）**：成本最低、完全可逆，并且保留了
「环境变了再跑一次」的能力 —— 这是环境配置技能唯一不可替代的价值。

---

## 2. 动手前的五道闸（每一档都走）

```
① 备份        cp -r <skill 目录>  $VW_CONFIG_ROOT/backup/skill-<名字>-<ts>/
② 列清单      把将被删/改的每一个路径列给用户看
③ 二次确认    等用户明确说"删吧"之类 —— 不用默认值或推断代替确认
④ 执行        删用 mv 到备份区再删，**不要**直接 rm -rf
⑤ 验证        test -f "$VW_CONFIG_ROOT/toolchain.json" && echo "契约仍在 ✓"
```

### 铁律

- **绝不 `rm -rf` 直接删技能目录。** 先 `cp -r` 到备份区，确认备份成功再删。
- **绝不碰 `/mnt/c`、`/mnt/d`。** `rollback.sh` 会主动拦截含这些路径的撤销命令。
- **用户问"能不能直接删"时，回答三档并解释取舍**，别只答"能"。

---

## 3. 为什么删掉环境配置技能是安全的

**契约文件在两个 Skill 的目录之外**：

```
~/.config/ideaform/          ← 不在任何 skill 目录内
├── toolchain.json           ★ 工作流技能唯一需要的东西
├── env.sh
├── install-manifest.jsonl
├── backup/
└── logs/
```

删掉 `skills/ideaform-setup/` 不会碰到它。所以：

```bash
test -f "$VW_CONFIG_ROOT/toolchain.json" && echo "契约仍在 ✓ → 工作流不受影响"
```

反过来，如果你**误删了契约**，也可以用 `rollback.sh --purge-contract` 留下的备份恢复。

---

## 4. 回滚：manifest 是唯一事实来源

安装阶段每完成一步就向 `install-manifest.jsonl` **追加**一条（append-only，
所以任何中途中断都能完整回滚）：

```jsonl
{"ts":"...","kind":"mkdir","target":".../lmms","detail":"LMMS 安装目录","undo":"rm -rf '.../lmms'"}
{"ts":"...","kind":"pip-install","target":".../bin/python","detail":"edge-tts>=7.3.1 soundfile","undo":".../bin/pip uninstall -y edge-tts soundfile"}
{"ts":"...","kind":"backup-file","target":"~/.lmmsrc.xml","detail":"备份于 backup/20261015-0900/","undo":"cp -a 'backup/.../lmmsrc.xml' '~/.lmmsrc.xml'"}
{"ts":"...","kind":"edit-file","target":"~/.lmmsrc.xml","detail":"stkdir → ...","undo":"cp -a '<备份>' '~/.lmmsrc.xml'"}
{"ts":"...","kind":"lmms-extract","target":".../squashfs-root/AppRun","detail":"AppImage 解包","undo":"rm -rf '.../squashfs-root'"}
```

**改文件类一律用「从备份还原」，不做反向字符串替换** —— 反向替换容易写错且不可靠。

### 用法

```bash
bash skills/ideaform-setup/scripts/rollback.sh                 # 列出会撤销什么（不动手）
bash skills/ideaform-setup/scripts/rollback.sh --dry-run       # 逐条演习
bash skills/ideaform-setup/scripts/rollback.sh --yes           # 真回滚（逆序）
bash skills/ideaform-setup/scripts/rollback.sh --only pip-install --yes   # 只撤某类
bash skills/ideaform-setup/scripts/rollback.sh --purge-contract --yes     # 连契约一起删
```

**逆序执行**（后装的先撤），避免依赖倒挂。

### 实测输出（假清单验证）

```
将按【逆序】撤销 4 条：
 1. [evil] /mnt/c/Users/x
✗       撤销命令指向 Windows 盘，已拒绝执行
 2. [backup-file] $HOME/.lmmsrc.xml
      撤销: cp -a 'bk/lmmsrc.xml' '$HOME/.lmmsrc.xml'
 3. [pip-install] .../bin/python
      撤销: '.../bin/pip' uninstall -y edge-tts soundfile
 4. [mkdir] .../lmms
      撤销: rm -rf '.../lmms'
```

## 5. 默认不清契约

`rollback.sh` **默认保留** `toolchain.json` —— 那是工作流技能要用的。
只有用户明确要求 `--purge-contract` 才删，而且删之前会先备份。

删掉契约后工作流技能会报"找不到契约，请先跑环境配置技能" —— 这是**预期行为**，
不是 bug。恢复方式：从 `$VW_CONFIG_ROOT/backup/` 取回，或重跑环境配置技能。

---

## 6. 环境配置技能本身的安全边界

| 行为 | 是否允许 |
|---|---|
| 只读探测（`detect.py`） | ✅ 从不写系统 |
| 写契约到 `~/.config/ideaform/` | ✅ 只写这个目录 |
| 在 venv 里 `pip install` | ✅ 用户级，可 `pip uninstall` 回滚 |
| 下载 LMMS 到 `$VW_CONFIG_ROOT/lmms/` | ✅ 用户级，可删目录回滚 |
| 改 `~/.lmmsrc.xml` 的 `stkdir` | ⚠️ **改前必先备份**（manifest 会记） |
| 碰 `/mnt/c`、`/mnt/d` | ❌ 绝对禁止 |
| 用 `sudo` / 装系统包 | ❌ 不用（沙箱拿不到 root，且没必要） |
| 删除用户的其它文件 | ❌ 不做 |

**需要 root 的活**：脚本会**停下来打印命令**，交给用户在自己终端执行，不自己试 `sudo`。

## 7. 会话结束前的自检

```bash
# 契约完整性
python3 skills/ideaform-setup/scripts/detect.py          # 退出码 0 = 齐备

# 回滚能力
bash skills/ideaform-setup/scripts/rollback.sh --list     # 能看到清单 = 可回滚
```

若用户选了"禁用"，验证一下：

```bash
grep '^disable:' skills/ideaform-setup/SKILL.md          # 应为 true
test -f "$VW_CONFIG_ROOT/toolchain.json" && echo "契约仍在 → 工作流可用 ✓"
```
