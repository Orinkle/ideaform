# 02 · 工作流总览

> 四阶段流水线，一条时间主轴，三个下游全部从它派生。

---

## 全景

```
                       ┌──────────────────────────────────────────┐
   用户输入            │  ①  文稿                                 │
   （主题/材料/想法）─→│     分层 script.md  +  台词.txt           │
                       └────────────────┬─────────────────────────┘
                                        │ 台词
                                        ▼
                       ┌──────────────────────────────────────────┐
                       │  ②  TTS 定轴   ★ 时间主轴从这里长出       │
                       │     量自然语速 → 排时间轴 → 出配音音轨     │
                       │     产出 plan.json / timeline.ts / voice │
                       └───────┬──────────────────────┬───────────┘
                               │ 时间轴 + 层次标注     │ 帧数
                               ▼                       │
       ┌──────────────────────────────────────┐        │
       │  ③  BGM 变奏                          │        │
       │     层次边界 → 变奏计划 → LMMS 出音频  │        │
       │     产出 bgm-plan.json / bgm.wav      │        │
       └──────────────────┬───────────────────┘        │
                          │ BGM 音轨                    │
                          ▼                             ▼
       ┌──────────────────────────────────────────────────────────┐
       │  ④  成片                                                  │
       │     Remotion 排画面（帧数=时间轴）＋ 集成两条音轨 ＋ 渲染  │
       │     ＋ 封面（构造主义静态 composition）                     │
       │     产出 final.mp4  +  cover.png                          │
       └──────────────────────────────────────────────────────────┘
```

---

## 阶段职责表

| 阶段 | 输入 | 做什么 | 产出 | 关键约束 |
|---|---|---|---|---|
| ① 文稿 | 用户任何形式的输入 | 写成**分层**的解说稿 + 一行一句的台词 | `script.md`、`台词.txt` | **必须分层**（阶段三要用） |
| ② TTS 定轴 | `台词.txt` | 量自然语速、排时间轴、合成音轨 | `plan.json`、`timeline.ts`、`voice.wav` | **先配音后定轴**（顺序铁律） |
| ③ BGM 变奏 | `plan.json` + 层次标注 | 层次边界 → 六个叙事功能 → 变奏计划 → LMMS 出音频 | `bgm-plan.json`、`bgm-plan.md`、`bgm.wav` | 变奏点必须落在层次边界 |
| ④ 成片 | `timeline.ts` + 两条音轨 + `bgm-plan.json` | 排画面、集成音轨、渲染、出封面 | `final.mp4`、`cover.png` | 帧数=时间轴；封面轴线不穿字 |

---

## 数据流：谁依赖谁

```
台词.txt ──┬─→ plan.json ──┬─→ bgm-plan.json ──→ bgm.wav ──┐
           │               │                               │
           └─→ timeline.ts ┘──→ TOTAL_FRAMES ──→ video.mp4 ─┼─→ final.mp4
                                   voice.wav ────────────────┘        │
                                                                      ▼
                                                               verify-video.py
```

**`plan.json` 是全流程的枢纽**：

- 阶段三读它的 `cues[].start/end` 定变奏边界
- 阶段四读它派生的 `timeline.ts` 定帧数与幕边界

**改一句台词 → `plan.json` 变 → 下游全部要重跑。** 这是唯一的"牵一发动全身"处，
所以脚本都带缓存与断点续跑（TTS 缓存键带内容哈希，渲染分段可跳过已完成段）。

## 校验门禁

每个阶段都有**客观校验器**，不过就不许进下一阶段：

| 阶段 | 校验 | 工具 |
|---|---|---|
| ② | 非静音 / 无削波 / 时长与规划偏差 < 50ms | `make-tts-track.py` 内置 |
| ③ | 非静音 / 无削波 / **各段确有差异**（否则变奏没落地） | 见 `stage3-bgm.md` §6 |
| ④ 画面 | 帧数严格相等 / 时长 / 音轨码率 > 64kbps | `verify-video.py video` |
| ④ 封面 | 尺寸 / 底色 / 文字像素 / **轴线不穿字** / 净空 | `verify-video.py cover --layout cover` |

**全部以非零退出码表示失败**，可直接串进 `&&` 流水线。

## 风格统一

画面与封面共用 `src/theme.ts`（调色板 / 字体 / 栅格 / 字号），
规范见 `skills/ideaform/references/constructivist-style.md`。

所以**不需要**"把封面风格对齐正片"这一步 —— 它们本来就是一个系统。

## 时间开销参考（本机实测）

固定成本（每次会话一次）：

| 项 | 耗时（冷 / 热） |
|---|---|
| 只读探测 | ~5 s |
| 冒烟校验 | 冷 ~90 s / 热 **~7 s**（2026-10-15 实测 6.7 s 四项全过） |
| LMMS 渲染 | ~1 s / 秒音频 |
| Remotion 打包 + 渲 1 帧 | 冷 ~60 s / 热 ~2–8 s |
| Remotion 渲成片 | **0.05–0.17 s/帧**，与画面重量强相关（demo 1414 帧实测 67 s ≈ 21 帧/s，1080p `--concurrency=3`） |

一条 60 秒 / 1800 帧的片子，热机下渲染约 2–5 分钟。
长片用 `skills/ideaform/scripts/render-segments.sh`：分段 + 每段核帧数 + 断点续跑
（重跑同命令自动跳过已完成段），防"一条命渲两小时、中断全白干"。

**长片（>3 分钟）必须分段渲染**（原因见 `stage4-render.md` §3）。

## 别做的事

| 反模式 | 为什么不行 |
|---|---|
| 先写好分镜帧号再让 TTS 去挤 | 被迫压缩语速，实测 1.218x |
| 每段都变奏 | 对比被稀释，反而听不出层次 |
| 变调 / 变速来表示层次 | 那是"切歌"不是"变奏" |
| BGM 音量拍脑袋写 `0.17` | 只压到之下 5.6 dB，密集口播偏吵；应用实测 RMS 反推 |
| 手写 `.mmp` XML | 属性漏一个就静音，用 Python 生成 |
| 渲染时不设 `TMPDIR` | 写 10MB 的 `/tmp` → `ENOSPC` |
| 合流不加 `-map` | 挑中 Remotion 的静音轨 → 成片没声音 |
| 用形容词交付（"画面应该没问题"） | 必须用数值校验 |
