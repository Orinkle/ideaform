# 05 · 故障排查

> 按**症状**查。每条都注明是 `[实测]` 还是推断。

---

## A. 环境配置阶段

### A1. `which ffmpeg` 是空，是不是没装？

**不是问题。** 系统通常没有 ffmpeg，但 Remotion 包里自带一份**精简版**：

```bash
find <remotion项目>/node_modules/@remotion -maxdepth 2 -type f -name ffmpeg
```

探测脚本会把它标为 `degraded`（在，但能力不全）。**够用。**
精简版**没有** `volumedetect` / `acompressor` / `dynaudnorm` / `alimiter`，
且 `loudnorm` 有前瞻延迟（会平移音轨、破坏字幕对齐）。

→ 结论：音量检测自己算（Python `wave`），对时间敏感的音轨只用 `volume` 做静态增益。

---

### A2. LMMS 渲染出来**全程静音，日志无报错**

**最贵的坑。** 真因：`~/.lmmsrc.xml` 的 `<paths stkdir="...">` 指向了不存在的目录。

```bash
python3 skills/ideaform-setup/scripts/detect.py   # 看 lmms 的 stkdir 行
#  · stkdir  ✓ ok      期望 .../squashfs-root/usr/share/stk/rawwaves
```

修：`bash skills/ideaform-setup/scripts/install.sh --only lmms`（会先备份 `.lmmsrc.xml`）。

**定位方法**：先渲染一个第三方已知能出声的工程做对照。它若也静音 → 是环境问题不是曲谱问题。

---

### A3. Remotion 报 `browserExecutable ... but the path doesn't exist`

`remotion.config.ts` 里 `Config.setBrowserExecutable("<绝对路径>")` 写死了旧路径
（换机器 / 清缓存后失效）`[实测]`。

**修**：`detect.py --write` 刷新契约（它会在 Remotion/puppeteer 缓存里重新找到 chrome，
写进 `tools.remotion.browser.resolved`，并由 `env.sh` 导出 `VW_CHROME`）。

**根治**：工程里**不要写死** `setBrowserExecutable`，改成：

```ts
if (process.env.VW_CHROME) Config.setBrowserExecutable(process.env.VW_CHROME);
```

（本项目的起始模板已按此写。）

---

### A4. 任何步骤报 `ENOSPC: no space left on device`

**不一定是磁盘满。** 本机 `/tmp` 是 **10MB tmpfs**，Remotion 打包 / `pip install`
/ AppImage 解包都会写它。

```bash
source ~/.config/ideaform/env.sh      # 会设 TMPDIR=$VW_TMPDIR（大盘）
echo "$TMPDIR"
```

`pip install` **也吃 TMPDIR**。

---

### A5. edge-tts 报 `WSServerHandshakeError: 403`

**先升级版本，再排网络。** 403 出在 WebSocket 握手阶段，不是网络问题
（`curl` 打 bing 返回 400 = 通）。

```bash
"$VW_VENV/bin/pip" install --upgrade "edge-tts>=7.3.1"
```

固定顺序：**① 升级 edge-tts → ② 校准系统时钟**（令牌按 5 分钟窗口算，偏差 >1 分钟必挂）
**→ ③ 才考虑代理**。

---

### A6. 中文渲染成方框（豆腐块）

字体族名没写完整。

```bash
fc-list :lang=zh family | grep -i "noto sans cjk"
fc-match "Noto Sans CJK SC"        # 确认命中，不是 fallback
```

样式里必须写**完整族名**：`"Noto Sans CJK SC Black"`，不能只写 `"Noto Sans"`。

> ⚠️ 像素校验**抓不到 tofu**（豆腐块也是像素）。要防它，只能先 `fc-list` 确认字体存在。

### A7. AppImage 跑不起来

```bash
# 沙箱无 /dev/fuse
chmod +x lmms.AppImage && ./lmms.AppImage --appimage-extract
./squashfs-root/AppRun --allowroot render x.mmp -f wav -o x.wav
```

`--allowroot` **必需**（沙箱内 `id` 显示 root，LMMS 默认拒绝以 root 启动）。
日志里 `Carla` / `JACK` / `VST` 类警告**无害**。

## B. 流水线阶段

### B1. 音频时长短了、整条与画面错位几秒

音轨**没带上留白**（`lead` + 所有 `gap` + `tail`）。
实测踩过：规划 59.47s，音轨只有 55.27s → **错位 4.2 秒**。

`--lines --audio` 已内置"每段带到位下句开始的留白"，收尾会核对偏差（应 < 50ms）。

---

### B2. 声音全错、画面对 —— 但不报错

TTS **缓存键只用了序号**，删改台词后序号整体平移，旧音频被当成"这条已合成过"而复用。

→ 缓存文件名必须是 `{序号}-{md5(语速|文本)[:8]}.mp3`（脚本已实现）。
修：删掉 `.tts/` 缓存重跑，或确认脚本是带哈希的版本。

---

### B3. 改了台词，但画面没跟上

`timeline.ts` 没同步进 Remotion 工程。时间轴是从台词长出来的，改台词会让后面所有 cue 平移。

```bash
cp out/timeline.ts <remotion项目>/src/timeline.ts
```

**画面侧的幕边界必须从 `CUES` 推导，不要手写帧号** —— 写死就必然错位。

---

### B4. 成片**没声音**（退出码 0、时长正确、能播放）

**十成是合流时没加 `-map`。** Remotion 输出的 mp4 自带一条**静音 AAC 轨**，
不加 `-map` 时 ffmpeg 自动选中它，真正的配音被丢掉（输出音轨只有约 2275 bps）。

```bash
ffmpeg -y -i silent.mp4 -i voice.wav -map 0:v:0 -map 1:a:0 \
       -c:v copy -c:a aac -b:a 192k -ar 48000 -ac 2 -shortest out.mp4
```

**自检**：

```bash
AB=$(ffprobe -v error -select_streams a:0 -show_entries stream=bit_rate \
     -of default=nw=1:nk=1 out.mp4 | tr -d ' ,\r\n')
[ "${AB:-0}" -gt 64000 ] || echo "音轨疑似静音（${AB} bps）→ 检查 -map"
```

---

### B5. BGM 太吵，盖住解说

音量是拍脑袋写的。应该用**实测 RMS 反推**：

```bash
bash skills/ideaform/scripts/mix-av.sh --plan-only --voice voice.wav --bgm bgm.wav --drop 9
```

实测样例：旁白 -26.5 dBFS、BGM -16.7 dBFS → `volume ≈ 0.12`。
`0.17` 只压到之下 5.6 dB，对密集口播明显偏吵。
目标区间：**BGM 比旁白低 8~12 dB**。

---

### B6. BGM 渲染出来各段一模一样（变奏没落地）

变奏计划写了，但**没写进工程**。检查：

- `bgm-plan.json` 里各 `texture.layers / velocity / register` 是否真的不同
- 生成器是否按 `start_tick/end_tick` 分段放了不同的音符
- 渲染后量**分段 RMS**：若全片一条直线，说明变奏没生效

## C. 渲染阶段

### C1. 渲染中途超时 `waiting for the page to render ... timeout 33000ms exceeded`

**根因不是代码**，是并发太高把内存顶爆（4 个 chrome 各开 1080p 页面）
→ 事件循环被卡住 → 超过 `delayRender` 30s 超时被判死。实测 12959 帧的片子挂在 5824 帧。

**修**：分段渲染 + 降并发。

```bash
npx remotion render <Id> out/chunk_00.mp4 --frames=0-2591 --concurrency=3
# 每段渲完立刻核 nb_frames
printf "file 'chunk_00.mp4'\nfile 'chunk_01.mp4'\n" > list.txt
ffmpeg -y -f concat -safe 0 -i list.txt -c copy out/video.mp4
```

`--frames=A-B` 是**闭区间**。分段的好处是**炸一段只重跑一段**。

---

### C2. `ffprobe` 读出「帧数校验失败 got=2592, want=2592」

**是取值错了，不是渲染错了。** `-of csv=p=0` **会带尾逗号**：

```bash
ffprobe -v error -select_streams v:0 -show_entries stream=nb_frames -of csv=p=0 f.mp4
# 实测输出: 2592,      ← 尾逗号！"2592," != "2592" 恒为真
```

**正解**：

```bash
nbframes() { ffprobe -v error -select_streams v:0 -show_entries stream=nb_frames \
             -of default=nw=1:nk=1 "$1" 2>/dev/null | tr -d ' ,\r\n'; }
```

这个坑实测**害我白重渲了一整段**。

---

### C3. `npx remotion render --help` 也报 `ENOSPC`

`--help` 会**先打包整个项目**再输出帮助。
→ 查参数优先读 `node_modules/@remotion/cli/dist/` 源码，别依赖 `--help`；并且带 `TMPDIR`。

---

### C4. 找不到 composition

```
Error: Could not find composition with ID The. Available compositions: A, B, C
```

用 `compositions` 命令枚举时，**可读输出里混着说明文字**（"The following compositions are available:"），
宽松正则会抓出 `The`。

→ 双通道抽取：① 错误信息里的 `Available compositions: A, B, C`；② 整行就是一个标识符。
（`verify.py` 的 `parse_comp_ids()` 已实现。）

## D. 封面 / 像素校验

### D1. 标题被对角轴切成两半

**本项目实测踩过的唯一成片级版式错误。** 轴线从文字块上穿过去了。

**规则**：轴线在文字块底边处的 y 必须 **> 文字块底边 + 0.08H**。

**两种修法**：下沉轴线 / 给文字块加纸色面板（让轴线从字后面穿过）。

**自检**：`verify-video.py cover --layout cover` 的 `P5` —— **文字块内红色像素 < 60**。
注意加 `--layout cover`：默认取样带是按视频场景调的，量封面会误报（见 D2）。

---

### D2. 像素校验误报（明明没问题的图被判失败）

六个常见根因：

1. **容差太松** → 相近色互相误判。`paper` 与 `paper2` 三通道差只有 (13,17,25)，
   容差 26 时互相命中。→ **容差收到 ~12，用"最近色"而不是"首个匹配"**。
2. **取样带用了别的版式** → 本技能自带封面板式，其红字标在 ≈0.48–0.56H、正文下行到 ≈0.71H；
   而默认取样带是按**视频场景**（无红字标题、正文不占走廊）调的。
   用场景带量封面 → P5「轴线穿字」与 P7「走廊异物」**双双假阳性**，图其实完全正确。
   → 加 `--layout cover`。实测：同一张封面默认带 P5=2074 判失败，`--layout cover` 下 P5=0、走廊 0.00% 通过。
3. **取样点撞到字形** → 静态点上出现"纸白色"不代表元素没渲染，可能那正是字。
4. **期望值依赖内容** → 标题变长 → 文字块变高 → 原采样窗口失效。
   → 用 `--text-band` / `--red-band` / `--corridor` 显式指定，别写死坐标。
5. **淡色污染** → 用 `min(r,g,b) < 150` 而不是颜色等值比较。
6. **`minrun` 太高** → 窗口里本来就有文字，行覆盖率达不到阈值 → 误报"未找到"。

> 换版式（改 hero 字号、挪文字块）后务必**拿新渲染实测一遍像素分布再定带**，不要沿用旧坐标。

---

### D3. 封面元素不见了

组件里用了动画（`useCurrentFrame` / `Rise` / `opacity:0` 起始）。
**still 渲染时 `useCurrentFrame()` 恒为 0**，动画初值会让元素不可见。

→ 封面组件必须是**纯静态**的。

---

## E. 通用排查纪律

1. **后台跑长任务别用 `| tail` / `| head`** 收输出（进程被杀时缓冲区一起消失），
   一律 `> logfile 2>&1`。
2. **别信"两边自洽"** —— 解码结果 = 编码结果，但两者都错的情况真实存在。
   要拿物理事实（音符起始 tick、文件字节数）核。
3. **下载失败别留残骸** —— 半个文件比没文件更危险（会被后续误判为"已装"）。
   先删残骸再重试，并核对字节数。
4. **测不了就写"未验证"** —— 不要用推断冒充实测。
