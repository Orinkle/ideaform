# 阶段三 · BGM 变奏（用音乐的形态变化标记论述层次）

> 这是本工作流区别于「随便配个 BGM」的地方。
> 核心脚本：`scripts/bgm-plan.py`。

---

## 1. 要解决什么

用户的原话：

> 用 LMMS **基于解说音轨**制作 BGM，用音乐引导用户理解，
> **当论述进入新层次时通过变奏表示层次改变**。

拆成两个要求：

1. **BGM 要贴合解说音轨** —— 长度严格相等，段落边界对齐。
2. **层次变化要听得出来，但不能像切歌** —— 这就是「变奏」。

---

## 2. 为什么是变奏而不是换曲子

**身份要素保持不变，只变形态要素**，听众才会觉得
「还是同一段音乐，但它进入下一层了」。

| 必须保持一致（身份） | 可以变化（形态） |
|---|---|
| 主题动机细胞 | 配器（增删声部） |
| 调中心 | 密度（音符疏密 / 细分） |
| 基本速度 | 音区（上/下八度） |
| | 和声张力（自然音 → 借用和弦 / 七度） |
| | 节奏（增值 / 减值） |
| | 动态（力度档） |
| | 调式（相对大小调 / 同主音） |
| | 动机处理（模进 / 倒影 / 增值 / 碎片化） |

**动机细胞是变奏的灵魂** —— 一个 3~5 音的音程结构，整片都从它派生。
所有变奏都是这同一个细胞的不同**变形**（模进、倒影、增值、碎片化），
所以听起来始终"是它"，只是形态不同。

> 音程代数与动机变形引擎的完整方法见 `electronic-music-production` 的
> `references/08-无听觉作曲法`（本技能不自带，避免重复）。

---

## 3. 六个叙事功能（每层选一个）

| 功能 | 中文 | 意图 | 典型变化 |
|---|---|---|---|
| `present` | 呈现·引入 | 先给身份：只露动机，不要满 | 单声部、疏、低动态、无打击 |
| `develop` | 展开·深入 | 「多了东西」就是层次感 | +bass +律动层、动机模进、加七度 |
| `intensify` | 强调·冲突 | 把张力推上去 | 全声部、升八度、借用和弦、力度抬档 |
| `contrast` | 对照·转折 | **换质地而不是加音量** | 撤层、换音色、转调式、动机碎片化 |
| `resolve` | 收束·回归 | 做减法 | 回主调、动机增值、力度回落 |
| `sustain` | 持续·过渡 | **不动** | 层次未变时保持，别乱变奏 |

**`sustain` 很重要**：如果每个段落都变，对比就被稀释了。
层次没变的地方，音乐必须**稳住**。

---

## 4. 音乐的第二职责：引导听众的思路

只做变奏，音乐是**分段器**；音乐真正的修辞力是**带着听众想**——
在论断落地前先制造悬念（"要发生什么"），在论断处给释放（"原来如此"）。
听众是自己"想到"结论的，比被喊"注意！"记得牢得多。

> 层次变奏管「结构」（听众知道进入下一段了）；
> 思维引导管「论证」（听众跟着你把这个问题想完）。两者都要，一个都不能少。

### 4.1 怎么想：提问 → 铺垫 → 释放

- **提问**——关键反问/悬念句处，让音乐**悬起来**：和声不解决、织体收薄。
  不给答案，听众的脑子会自动去补。
- **铺垫**——论断将至，留白半拍（breath）。安静不是"强调技巧"，
  是给听众一个"要来了"的预期，让他的注意力自己走过来。
- **释放**——论断落拍时解决（回主和弦 + 一记同击），随后一小节力度略抬，
  像说完结论后自然的语气上扬，带着思路奔向下一站。

### 4.2 标在哪：思维节点，不是"重要句"

- **全文 2~4 个**：核心论断、关键转折、**反问句的答句**（问句处悬起、答句处释放，
  是最经典的一组）。标多了就没有引导了。
- **不要标**：层次起始句（变奏已经在那里说话了，两套语言叠在一起互相抵消）、
  过渡句、客套话。
- 判据：这句在**推进论证**吗？只是"重要"但不推进思路的句子，音乐不用插手。

### 4.3 写法与落地

```bash
"$VW_VENV/bin/python" scripts/bgm-plan.py \
    --plan out/plan.json \
    --layers "1:present,4:develop,6:resolve" \
    --accents "4,14,22,27" \
    --key "A minor" --out out/bgm-plan.json
```

`--accents` 是逗号分隔的 **cue 号**（= 台词序号，见 `plan.json` 的 `cues[].i`）。
产物 `bgm-plan.json` 的 `accents[]`：

```jsonc
{
  "cue": 14, "sec": 12.378, "tick": 1152,
  "bar": 7, "beat": 1,        // 已钉到第 7 小节第 1 拍（自由拍的重音像事故）
  "kind": "emphasis",
  "breath_ticks": 24,         // 前留 24 tick（半拍）空白 = 铺垫
  "lift": 14,                 // 其后一小节力度 +14（LMMS vol 单位）= 释放后的上扬
  "text": "……该句原文……"
}
```

渲染器（`bgm-from-plan.py` / composer）逐条落地：

| 时刻 | 动作 | 思维作用 |
|---|---|---|
| `tick - breath_ticks` | 旋律轨休止或力度减半 | 铺垫（预期） |
| `tick` | kick + 全声部同击一记 | 论断落地 |
| `tick ~ tick + 1 小节` | 所有轨 vol += `lift`，之后回落 | 带着思路往下走 |

重音**不改变身份要素**（动机 / 调性 / 基本速度照旧）——它是奏法，不是曲式。

### 4.4 校验（渲染后必做）

量**重音点前后各 0.5s 的 RMS**：落拍处应明显高于前后邻域
（经验判据 ≥ +2 dB）。若听不出 / 量不出 → 重音没写进工程
（同 B6：检查生成器是否真消费了 `accents[]`）。

## 5. 用法

```bash
# ① 把文稿的层次落到 cue 号上
#    写法 cue:功能
"$VW_VENV/bin/python" scripts/bgm-plan.py \
    --plan out/plan.json \
    --layers "1:present,4:develop,6:resolve" \
    --key "A minor" \
    --out out/bgm-plan.json

# 没人工标注时（**只是占位，务必人工标一遍**）
"$VW_VENV/bin/python" scripts/bgm-plan.py --plan out/plan.json --auto-layers 3 --out out/bgm-plan.json
```

关键参数：

- `--layers` —— 层次标注。`cue 号` 来自 `plan.json` 里每条台词的 `i`。
- `--key` —— 调中心（身份要素，全片不变）。
- `--bpm` —— 不传则**自动选**：在 66–96 BPM 里挑让「小节数为整」的那个，
  并列时优先**偶数小节**（乐句成对）。实测 24.414s → 68.8 BPM / 7 小节。
- `--lead-in` —— 变奏点相对层次边界**提前**多少秒。默认 0（与文字同时转向）；
  设 0.2~0.4 可让音乐**先动**，听众更容易被引导。

## 6. 输出

### `bgm-plan.json`（给 LMMS 侧消费）

```jsonc
{
  "bpm": 68.8, "key": "A minor", "bars": 7,
  "total_sec": 24.414, "total_ticks": 1344,       // ★ LMMS 单位
  "ticks_per_bar": 192,
  "mmp_hints": { "head_bpm": 68.8, "timeline_lp1pos": 1344 },
  "variations": [
    { "index": 1, "template": "present", "label": "呈现 · 引入",
      "start_sec": 0.3, "end_sec": 12.378,
      "start_tick": 0, "end_tick": 682, "len_tick": 682,
      "texture": { "layers": ["pad"], "density": "low", "register": 0,
                   "harmony": "diatonic-triad", "tension": 0,
                   "dynamics": "p", "rhythm": "half-note pulse",
                   "motif": "original (sole statement)", "percussion": "none",
                   "velocity": 62 },
      "changed_vs_prev": ["(起始段 —— 建立身份，尚无可比对象)"] }
  ]
}
```

### `bgm-plan.md`（人读 + 审计）

含一张变奏表，以及每段的「**变奏证据**」—— 相对上一段到底变了哪几项。
**这是可审计的**：相邻两段若 `changed_vs_prev` 为空，说明那里要么真没层次变化
（那就该用 `sustain`），要么层次标注漏了。

## 7. LMMS 侧落地

`bgm-plan.json` 是给 LMMS 生成器读的。要点：

1. **`bpm` 必须写进 `<head bpm="...">`**，`total_ticks` 写进 `<timeline lp1pos="...">`，
   否则 BGM 长度与解说对不齐（`lp1pos` 决定渲染终点，写小了曲子被截断）。
2. **tick 基准是 48/拍**（与常见 DAW 的 96/480 不同）：1 拍 = 48 tick，1 小节(4/4) = 192 tick。
3. **每个 `variations[]` 段落 = 工程里的一段**，按 `start_tick / end_tick` 放音符。
4. **变奏靠声部增删 + 音符参数实现**：
   - 配器变化 → 增删轨道（或在 `<pattern>` 里留空）
   - 密度 / 力度 → `<note vol="...">` 的密度与力度值
   - 音区 → `key` 整体 ±12
   - 打击 → 是否有 kick/hat 轨

> ⚠️ **必须用 `composer.py` 或 Python 生成 `.mmp`，不要手写 XML**（属性漏一个就静音）。
> 引擎与 schema 见 `electronic-music-production` 的 `references/06-文字到曲子引擎`；
> `.mmp` 语法、插件参数、`eldata` 包络见其 `references/05`。

5. **渲染**：

```bash
"$VW_LMMS_APPRUN" --allowroot render bgm.mmp -f wav -o out/bgm.wav
```

`--allowroot` 必需（沙箱内 `id` 显示 root，LMMS 默认拒绝以 root 启动）。
日志里 `Carla` / `JACK` / `VST` 类警告**无害**。

6. **渲染后必做的电平体检**（见 `srt-tts-voiceover` §10 的判据）：

| 项 | 判据 |
|---|---|
| 非静音 | 峰值 > 1000 且 RMS > 100 |
| 无削波 | 满刻度样本 < 0.01% |
| 结构递进 | 分段 RMS 符合预期（如 A < B < C） |
| **变奏真的发生了** | 各段 RMS / 频带能量**确有差异** —— 若全片一条直线，说明变奏没写进工程 |

---

## 8. ⚠️ 三个必踩的坑

1. **`eldata` 的 `amt="0"` 会让整条包络静默失效** —— 音符一律满音量直上直下，
   听感就是"死板、僵硬、机械"。**`amt` 必须非零。**
   （时间参数换算：实际秒数 ≈ `5 × 参数²`，即 `参数 = sqrt(秒/5)`。）
2. **`stkdir` 指向不存在的目录 → 全程静音且不报错。**
   契约里的 `tools.lmms.stkdir_ok` 必须是 `true`；否则先修环境再作曲。
3. **加混响会把总电平抬高** —— 加完必须**重新分配各轨电平**，别只调总线。

---

## 9. BGM 与解说的电平关系

BGM 是**衬底**不是伴奏。目标：**比旁白低 8–12 dB**。

不要拍脑袋写 `volume=0.17`，用实测 RMS 反推（见阶段四的 `mix-av.sh --plan-only`）：

```
gain_dB = (旁白RMS - D) - BGM原始RMS
volume  = 10 ** (gain_dB / 20)
```

实测样例：旁白 -26.5 dBFS、BGM -16.7 dBFS、取 D = 8.6 → `volume ≈ 0.12`。
**`0.17` 只压到之下 5.6 dB，对密集口播明显偏吵。**

> 注意：音乐 RMS 是连续的、语音 RMS 中间有大量静音，
> 所以**别直接拿两者的整体 RMS 相等来配** —— 差 8~12 dB 听起来才「是衬底而不是伴奏」。
