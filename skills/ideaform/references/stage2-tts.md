# 阶段二 · TTS 定轴（时间主轴从语速里长出来）

> 全部 `[实测]`。核心脚本：`scripts/make-tts-track.py`（自带契约衔接，直接可跑）。

---

## 1. 顺序铁律（本工作流最容易被违反的一条）

```
① 写台词
② make-tts-track.py --lines 台词.txt --fps 30 --audio   ← 量自然语速，排出时间轴
③ 拿输出的 TOTAL_FRAMES 去写 Remotion composition       ← 帧数由此确定
④ 再渲染
```

**反例代价 `[实测]`**：先按分镜写死 43 条时间码，TTS 自然语速合计 **212.90s**，
而视频只有 **174.80s** → **被迫压缩 1.218x**，只能靠 35 条逐条提速硬凑。
虽然最终残余失真只到 1.042x、听不出来，**但这妥协本来完全可以避免**。

同一批台词若按自然语速定轴，正确结果是 **6741 帧 / 224.70s @30fps**，
而不是事后被压到 5244 帧 / 174.80s。

---

## 2. `--lines` 模式（为这一步而生）

```bash
"$VW_VENV/bin/python" scripts/make-tts-track.py \
    --lines 台词.txt --fps 30 --audio \
    [--lead 0.3] [--gap 0.25] [--tail 1.0] \
    [--plan-out out/plan.json] [--ts-out out/timeline.ts]
```

- `--audio` **顺带把音轨也出了**，且因为时间轴就是按自然时长排的，
  槽位长度恰好等于语音长度，`atempo` 全程为 1.0 ⇒ **音轨 100% 原速原声，一次都不用变速**。
- 不加 `--audio` 就只量语速排轴、不出音轨。
- 输出可直接用的 `.ts`：

```ts
export const FPS = 30;
export const TOTAL_FRAMES = 732;
export const CUES = [
  { start: 9, end: 114, text: "这是《文稿即时间轴》的第一层。" },
  ...
] as const;
```

- `--gap` 是关键调节钮：**条间留白越长，节奏越从容、成片越长。先定 gap，再定帧数。**
- 改完台词必须把生成的时间轴**同步给画面**（`cp out/timeline.ts <项目>/src/timeline.ts`），
  否则画面还停在旧的帧数上。

## 3. 实测样例（6 条台词）

```
   1   3.50s   105帧   「这是《文稿即时间轴》的第一层。」
   2   4.27s   128帧   「解说音轨才是整条流水线的时间主轴。」
   3   3.55s   107帧   「画面帧数由它决定，不是反过来。」
   4   3.48s   104帧   「第二层开始了，音乐在这里变奏。」
   5   4.32s   130帧   「层次切换用变奏表示，而不是换一首曲子。」
   6   2.74s    82帧   「最后收束回主调。」

自然语速合计 21.86s
加留白后成片时长 24.41s = 732 帧 @ 30fps
归一化：实测峰值 -5.80 dBFS → 目标 -1.00 dBFS（增益 +4.80 dB）
与规划时长核对：24.414s vs 24.414s  偏差 0.0 ms → ✔ 通过
```

中文口播语速经验值：**约 4.5–5.5 字/秒**。22 字一句 ≈ 4.3s。

## 4. ⚠️ 音轨必须带上留白，否则整条与画面错位

只把"纯语音"顺序拼起来是不够的 —— 那样音轨会短掉 `lead + 所有 gap + tail`。

**实测踩过**：规划 59.47s，音轨只有 55.27s，**整条错位 4.2 秒**。

正确做法：**每段带"到下一句开始为止"的留白**，最后一段带 `tail`，最前面补 `lead` 的静音。
`--lines --audio` 已内置这一步，收尾会核对 `音轨时长 == 规划时长`（偏差 < 50ms）。

---

## 5. ⚠️ 缓存键必须带内容哈希，不能只用序号

按"第 N 条"缓存音频，一旦删改台词，**后面的序号整体平移，旧音频会被当成"这条已合成过"而复用**
—— 结果画面对、声音全错，且不报错。实测踩过。

→ 缓存文件名用 `{序号}-{md5(语速|文本)[:8]}.mp3`（脚本已实现 `clip_name()`）。

---

## 6. edge-tts 排障顺序（**先升级版本，再排网络**）

合成报 `WSServerHandshakeError: 403, message='Invalid response status'`：

- 403 出在 WebSocket **握手**阶段，**不是网络问题**。
- `curl https://speech.platform.bing.com/` 返回 **400**（即连通），摘掉 `http_proxy` 也一样 403。

**唯一正确处理**：

```bash
"$VW_VENV/bin/pip" install --upgrade "edge-tts>=7.3.1"
```

实测 `7.2.8` 全量 403 → 升到 **`7.3.1` 立刻恢复**。

**固定排查顺序：① 升级 edge-tts → ② 校准系统时钟**（令牌按 5 分钟窗口算，偏差 >1 分钟必挂）
**→ ③ 才考虑代理。** 别一上来就怀疑 IP 被封。

## 7. 声线（zh-CN，实测全部可用）

| 声线 | 特点 |
|---|---|
| `zh-CN-YunxiNeural` | 男·年轻活泼 —— **解说最常用（默认）** |
| `zh-CN-YunyangNeural` | 男·新闻播音，稳重 |
| `zh-CN-YunjianNeural` | 男·激情（体育/解说） |
| `zh-CN-XiaoxiaoNeural` | 女·温柔 |
| `zh-CN-XiaoyiNeural` | 女·活泼 |

⚠️ `zh-CN-YunxiNeural` 会**偶发** `NoAudioReceived`（同一句第一次失败、重试即成功）。
**必须重试 3~5 次 + 退避**，别一次失败就换声线或判定接口不可用（脚本已内置重试）。

---

## 8. 声线一致性

**整片用一个声线。** 换声线 = 换讲述者，听众会出戏。
若某一段确需不同语气，用 `rate=` / `pitch=` 微调，不要换声线。

---

## 9. 交付形态

- **WAV 母版**（`pcm_s16le`，48kHz/2ch）：给集成用，无损、时间精确。
- **MP3 便捷版**（`libmp3lame -b:a 192k`）：试听/分发。mp3 因编码器 padding 会略长几十 ms，正常。
- 交付前提醒：若成片已烧字幕，**别再把 SRT 当字幕轨挂上去**（会叠字），SRT 只作配音脚本。

## 10. 本阶段出口 → 下一阶段的接口

| 产物 | 谁消费 | 消费什么 |
|---|---|---|
| `plan.json` | `bgm-plan.py`（阶段三） | `cues[].start/end`、`total_sec`、`fps` |
| `timeline.ts` | Remotion（阶段四） | `TOTAL_FRAMES`、`CUES[].start/end` |
| `voice.wav` | 音轨集成（阶段四） | 整条作为解说轨 |

**`plan.json` 是本工作流的枢纽文件** —— 阶段三的变奏边界和阶段四的帧数都由它派生。
