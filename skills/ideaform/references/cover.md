# 封面（构造主义 · 静态 composition）

---

## 1. 三条铁律

1. **`durationInFrames={1}`。** 封面是静帧。
2. **组件内禁用动画。** `useCurrentFrame()` 在 still 渲染时恒为 `0`，
   任何以动画初值开始的元素（`opacity: 0`、`scale(0)`）都会**不可见**。
   不要用 `Rise`/`Wipe`/`useEnter` 这类入场组件。
3. **一切数值来自 `theme.ts`**，不写死颜色与字号 → 与正片天然一致。

---

## 2. 参数化：一套版式复用 N 期

```tsx
<Composition id="Cover" component={Cover}
             durationInFrames={1} fps={30} width={1920} height={1080}
             defaultProps={{
               kicker:   "构造主义解说视频",
               title:    "文稿即时间轴",
               subtitle: "解说音轨决定画面帧数，音乐变奏标记论述层次",
               episode:  "07",
             }} />
```

换内容只改 props，不碰版式：

```bash
npx remotion still Cover out/cover-07.png --props='{"kicker":"...","title":"...","subtitle":"...","episode":"07"}'
```

> 把可变文字集中到 `src/episodes.ts` 之类的数据表更好 —— 组件只读 props。

## 3. 版面骨架

```
■ EP 07                                   ← 左上：红方块 + 等宽编号
   构造主义解说视频                        ← kicker（红，等宽，字距 8）
   文稿即时间轴                            ← hero（墨黑，重体，字距 -2）
   ─────────────────────                  ← 分隔线（rule 色，2px）
   解说音轨决定画面帧数…                   ← 副标题（ink2，最大宽 900）
                     ╱╱╱╱                  ← 对角轴（墨细 + 红粗，走在文字下方）
                                   ┌────┐
                                   │墨块│  ← 右下压角（420×300）
                                   └────┘
```

关键坐标（1920×1080）：

| 元素 | 位置 |
|---|---|
| 系列标识 | `left: 120, top: 120`（56×56 红方块 + `EP nn`） |
| 文字块 | `left: 120, top: 0.26H (=281)`，宽度 `1920 - 240 - 420` |
| 对角轴 | `(-160, 1.12H) → (2120, 0.52H)`，红线 y 偏移 +14 |
| 压角块 | `right: 0, bottom: 0`，420×300 |

## 4. ⚠️ 实测踩过的版式错误：轴线穿过标题

**第一版**把轴线从 `0.82H → 0.18H` 拉，结果红黑双线**从标题「轴」字上穿过**，
标题右半截被切开，完全不可读。

**规则**：轴线在文字块底边处的 y 值必须 **> 文字块底边 + 0.08H**。

**两种修法**：

- **下沉轴线**（本次采用）：`y1=1.12H, y2=0.52H`，让它在文字下方横穿。
- **压纸色面板**（更构造主义）：给文字块加 `background: PAL.paper` + 内边距，
  让轴线看起来从文字后面穿过 —— El Lissitzky 式图层手法。

### 自检（可程序化）

```bash
python3 scripts/verify-video.py cover out/cover.png --layout cover
# ✗ [P5] 标题区内红色像素 2074 ← 红线穿字（或取样带用错，见下）
# ✓ [P5] 标题区内红色像素 0
```

判据：**文字块矩形内不应出现强调红** → 红色像素 < 60。
这比"走廊纯净度"更精准，直接盯住轴线撞进文字的那种失败。

### ⚠️ 取样带必须按版式选（实测误报，别踩）

判据里的采样窗口**默认按视频场景调**（标题在上、轴线远在下方）。
本技能**自带封面板式**，而封面版式与场景不同：

| 版式 | 标题 | 红字 | 正文 | 轴线 |
|---|---|---|---|---|
| `scene` 视频场景 | 0.34H 起 | 无 | 无 | 远在下方 |
| `cover` 封面 | 0.26H 起、更大 | **红「构想」字标 ≈0.48–0.56H** | **下行到 ≈0.71H** | ≈0.76H 起 |

用 `scene` 的带去量封面 → **红字标被当成"轴线穿字"、正文被当成"走廊异物"**，
两项齐报错，而封面其实完全正确（实测：P5=2074 假阳性 → 换带后 P5=0、走廊 0.00%）。

```bash
verify-video.py cover out/cover.png --layout cover      # 封面用这个
verify-video.py cover out/cover.png                     # 默认 scene，量场景帧用
```

三个带都能单独覆盖：`--text-band` / `--red-band` / `--corridor`（分数坐标 `y0,y1,x0,x1`）。
换版式（改 hero 字号、挪文字块）后采样窗口会失效 —— **拿新渲染实测一遍像素分布再定带**，
不要沿用旧坐标。

## 5. 六个像素判据

| ID | 检查 | 判据 | 抓什么 |
|---|---|---|---|
| P1 | 尺寸 | 1920×1080 | 尺寸配错 |
| P2 | 文件体积 | > 20 KB | 渲染失败（空图） |
| P3 | 底色 | 四角最近色 ∈ {paper, paper2} | 背景没渲染 / 配色错 |
| P4 | 文字渲染 | 文字区墨色像素 > 300 | 字体缺失、`opacity:0` 残留、被同色底盖住 |
| P5 | **轴线不穿字** | 标题区红色像素 < 60 | 版式碰撞 |
| P6 | 强调色存在 | 全图红色像素 > 50 | 强调色丢了 |
| P7 | 净空 | 文字下方走廊异物率 < 1.5% | 元素重叠 |

### 判据的通用坑

1. **容差太松会让相近色互相误判。** `paper (239,232,219)` 与 `paper2 (226,215,194)`
   三通道差只有 (13,17,25) —— 容差 26 时互相命中。
   → **容差收到 ~12，并用"最近色"而不是"首个匹配"**。
2. **取样点会撞到字形。** 静态点上出现"纸白色"不等于元素没渲染 —— 可能那正是字。
3. **期望值依赖内容。** 标题变长 → 文字块变高 → 原来的采样窗口可能失效。
   → 用 `--text-band y0,y1,x0,x1` 显式指定，别写死坐标。
4. **`min(r,g,b) < 150` 比颜色等值比较更稳健** —— 纸色/淡纹样通过，
   文字/实心块/彩线必然被判为异物；且不受淡色污染影响。

## 6. 交付

封面与成片**同时**落工作空间，并做 md5 回读比对：

```bash
md5sum out/cover.png "$DST/cover.png"    # 两行哈希必须一致
```

尺寸与字节数下限也检查一下（PNG < 20KB 基本是渲染失败）。
