# 构造主义视觉规范（画面与封面共用）

> 风格要求：**构造主义，干净简约**。
> 画面与封面共用同一套调色板 / 字体 / 栅格 —— 所以它们天然一致。
> 单一事实来源：Remotion 工程里的 `src/theme.ts`（本技能自带的模板已内置）。

---

## 1. 构造主义是什么（可执行的三条）

不是"苏联海报滤镜"，是三条可落地的构图原则：

1. **几何优先于装饰。** 用矩形、直线、对角轴组织画面。不用花边、渐变、阴影球。
2. **非对称平衡。** 主体偏一侧，用一块几何色块或一条轴线在另一侧压住。
   居中对称是构造主义的反面。
3. **一个强调色。** 全片只用 **一种** 彩色（本项目用红），
   且只在**需要指认重点**的地方出现。彩色越多，越不构造主义。

配套的两条减法原则：

4. **大留白。** 纸色面积应显著大于墨色面积（经验：墨+红 < 35%）。
5. **重体字、紧行距、少字号级。** 一套版式只用 2~3 个字号级。

## 2. 调色板

```ts
export const PAL = {
  paper:  "#EFE8DB",   // 纸白（偏暖）—— 底
  paper2: "#E2D7C2",   // 次级纸色 —— 块面
  ink:    "#17140F",   // 墨黑 —— 主文字 / 主色块
  ink2:   "#3A342C",   // 次级墨 —— 注释 / 细线
  red:    "#CE2A1D",   // 强调红 —— **唯一的彩色**
  rule:   "#C9BFA9",   // 栅格线
} as const;
```

⚠️ **没有第五个颜色。** 要"再加个色"的时候，先问能不能用墨色的深浅解决。

### 为什么是暖纸色而不是纯白

纯白底 + 纯黑字是"文档感"；暖纸色 + 暖墨黑是"印刷品感"，
更贴近构造主义的历史媒介（凸版印刷、海报），也更耐看。

---

## 3. 字体

```ts
export const FONT = {
  display: '"Noto Sans CJK SC Black", "Noto Sans CJK SC", sans-serif',
  body:    '"Noto Sans CJK SC", "Noto Sans CJK JP", sans-serif',
  mono:    '"Noto Sans Mono CJK SC", "Noto Sans Mono", monospace',
} as const;
```

**三条硬规矩**：

1. **中文必须写完整族名**（`"Noto Sans CJK SC Black"`）。只写 `"Noto Sans"` 会掉进
   **tofu（豆腐块）**。渲染前先确认字体存在：

```bash
fc-list :lang=zh family | grep -i "noto sans cjk"
fc-match "Noto Sans CJK SC"      # 确认命中，不是 fallback
```

2. **重体只用于标题。** 正文用 Regular/Medium。"全篇加粗"= 没有重点。
3. **拉丁字母与数字用等宽**（`FONT.mono`），配 CJK 有技术感，且数字对齐好看。

## 4. 画布与栅格

```ts
export const CANVAS = { w: 1920, h: 1080, fps: 30 } as const;
export const GRID   = 60;    // 栅格步长(px)
export const MARGIN = 120;   // 安全边距
export const TYPE = {
  hero: 132, h1: 84, h2: 56, body: 34, caption: 24,
} as const;
```

- **1920×1080 / 30fps** 是默认交付规格。
- **左右上边距 ≥ 120px**（约 6%）。下边距可小，因为底部常被进度条/字幕占据。
- **所有元素坐标取 `GRID` 的整数倍**（120/240/300…），画面自然对齐。
- 字号只用 `TYPE` 里的档位，不要临时加 47px 这种数。

---

## 5. 对角轴：构造主义的签名元素

一条从画面一侧穿到另一侧的**双线轴**（墨黑细线 + 红粗线，红在下偏移 12~14px）：

```tsx
const y1 = CANVAS.h * 1.12;   // 起点在画面外
const y2 = CANVAS.h * 0.52;   // 终点在画面外右侧
<line x1={-160} y1={y1} x2={CANVAS.w + 160} y2={y2} stroke={PAL.ink} strokeWidth={3} />
<line x1={-160} y1={y1 + 14} x2={CANVAS.w + 160} y2={y2 + 14} stroke={PAL.red} strokeWidth={10} />
```

**为什么起点/终点在画面外**：让轴线看起来"穿过"画面，而不是"画在"画面里 —— 有延伸感。

### ⚠️ 版式铁律：轴线不得穿过文字

**这是本项目实测踩过的唯一一个成片级版式错误。**

第一版把轴线从约 `0.82H → 0.18H` 拉，结果**红黑双线从标题「轴」字上穿过**，
标题右半截被切开，完全不可读。

**规则**：轴线在**文字块底边**处的 y 值必须 **> 文字块底边 + 0.08H**。

自检（`verify-video.py cover --layout cover` 的 `P5`）：

```
文字块矩形内不应出现强调红 → 红色像素 < 60
```

> ⚠️ **必须加 `--layout cover`。** 默认取样带是按视频场景（无红字标题、无下行正文）调的；
> 封面的红「构想」字标与正文会落进这些带里，导致 P5/P7 双双假阳性。
> 实测：同一张正确封面，默认带 P5=2074 判失败，`--layout cover` 下 P5=0 通过。

修法二选一：

- **下沉轴线**（推荐）：把 `y1/y2` 整体下移，让它在文字块下方横穿。
- **压一块纸色面板**（更构造主义）：给文字块加 `background: PAL.paper` + 内边距，
  让轴线看起来"从文字后面穿过"。这是 El Lissitzky 式的图层手法。

## 6. 版面骨架（推荐）

```
┌────────────────────────────────────────────┐
│ ■ EP 07                          (左上)    │
│                                            │
│   构造主义解说视频            ← kicker(红)  │
│   文稿即时间轴                ← hero(墨黑)  │
│   ───────────────────         ← rule 分隔   │
│   解说音轨决定画面帧数…        ← body(ink2)  │
│                                            │
│                        ╱╱╱╱╱  ← 对角轴      │
│                                        ┌───┤
│                                        │墨色│ ← 压角块
│                                        │块面│
│                                        └───┤
└────────────────────────────────────────────┘
```

- **左上**：系列标识（红方块 + `EP nn`，等宽字）
- **中左偏上**：文字块（左对齐，不居中）
- **右上 / 左下的对角**：留白
- **右下**：墨色块面压角，制造非对称张力

## 7. 画面侧（视频帧）

除了封面，正片画面遵循同样语言，但**动起来**：

- **幕与幕之间用几何转场**：色块横扫、轴线位移、栅格展开 —— 不要淡入淡出（太软）。
- **文字出场用位移 + 遮罩**，不用缩放弹跳。
- **所有动画由 `useCurrentFrame()` + `interpolate()` 驱动**
  —— **CSS transition / Tailwind 动画类在 Remotion 里不会渲染成帧**。
- **幕边界从 `CUES` 推导，不手写帧号**（见 `stage4-render.md`）。

## 8. 版式自检清单（无目视）

| 检查 | 方法 | 判据 |
|---|---|---|
| 尺寸 | PNG 头 | 1920×1080 |
| 底色 | 四角取样最近色 | `paper` / `paper2` |
| 文字渲染 | 文字区数墨色像素 | > 300 |
| **轴线不穿字** | 标题区数红色像素 | **< 60** |
| 净空 | 文字下方走廊异物率 | < 1.5% |
| 强调色存在 | 全图红色像素 | > 50 |

一处即查：`python3 scripts/verify-video.py cover out/cover.png --layout cover`

> ⚠️ 判据里的**坐标是分数**，会随文案与**版式**变化。标题变长时文字块变高，
> 封面（自带模板）与视频场景的取样带本来就不同。若用了不匹配的带导致误报，
> 用 `--layout cover` 切换版式预设，或用 `--text-band y0,y1,x0,x1` /
> `--red-band` / `--corridor` 显式指定。
> （"期望值依赖内容"是这类校验最常见的坑。）
